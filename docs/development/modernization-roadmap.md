# Panthesia：歌曲管理与演奏体验改造计划

更新：2026-11-19。此计划替代此前按 Synthesia 编号顺序推进的安排。主工程 D:\Music\_tools\Panthesia。

## 产品主线

用户导入一份 MIDI 后，能够在一首歌中管理演奏版本、谱面及练习条件，直接开始练习，按需转调和量化，使用 DuET 生成并采用谱面。管理、声音、谱面和瀑布围绕同一首歌、同一演奏版本和当前练习条件工作。

## 优先级与完成条件

| 批次 | 实际改造 | 完成条件 |
| --- | --- | --- |
| P1 数据核心与制谱接入 | 将练习变换移入核心领域；以已有作品 / 演奏 / 谱面登记为基础建立统一歌曲投影；DuET 接入软件生成任务，记录输入、生成器和派生结果 | 管理与谱面入口能看到同一数据关系；软件内真实生成 DuET MusicXML，并进入预览 / 采用 / 再次打开流程 |
| P2 管理闭环 | 同歌不同演奏与谱面版本集中管理；版本选择与采用；生成结果复用；DuET 逐音身份进入对齐；替换临时拼接路径 | 从选曲到采用谱面、切换版本再开始练习，均能在软件内完成 |
| P3 演奏工作区 | BPM、等音 / 连续即时切换、定位与循环、音源状态、谱面跟随；整理主次操作、缩减弹窗；处理瀑布掉帧 | 连续完成选曲、设置、练习、分段反复与回顾；声音与画面稳定、状态明确 |
| P4 成品体验与交付 | 琴键、瀑布、皮肤、特效和界面统一；清理被替代代码；迁移、安装 / 便携包 | 当前源码有对应成品，用户数据迁移明确，常用管理和演奏流程达到交付条件 |

元数据、来源覆盖、复杂分组与交换格式细节暂入后排，只有直接阻塞上述流程时处理。Synthesia 功能表用于覆盖检查，按产品收益重新排期。

## 数据核心

当前 P1 制谱闭环与 P2 歌曲 / 版本管理、逐音来源、量化重新记谱已落地。P3 已改造练习工具栏、BPM 编辑、实时模式队列、瀑布 / 琴键 / 特效缓存，接通 DuET 环境设置及谱面管理返回，并新增跨谱面 / 瀑布的 A/B 选段与统一循环。源码批次和实际运行证据见 modernization-handoff.md。P4 已集中外观 / 光效 / 网格设置，接入实际绘制器预览，并复用已完成的谱面排版。后续继续统一演奏表面与其余设置弹窗，整理剩余耦合和旧实现退出项，制作当前源码运行包并独立启动核对。整体 Goal 继续 active。

- 作品：同一音乐作品的身份与所属演奏版本。
- 演奏版本：原始 MIDI 内容身份、文件位置、速度与实际演奏时序。
- 谱面版本：MusicXML / MXL 内容身份、所属演奏、生成来源与采用状态。
- 练习变换：转调、量化网格、时值等参数；派生身份由源演奏与参数决定。
- 制谱结果：源演奏、生成器 / 模型 / 实现身份、输出和逐音映射，支持复用。

MusicXML 是主要乐谱交换格式，内部音乐语义独立于文件格式与显示器。DuET 默认读取原始演奏 MIDI；练习量化独立按需生成。Verovio 负责显示，MuseScore 负责编辑和 PDF 排版。ABC 作为按实际需求加入的适配项。

## 重构与迁移

允许替换旧实现、重写模块与界面、合并重复系统。被新入口替代的生产路径应退出；旧数据由一次迁移或明确适配接入，避免长期维护两套核心。保护对象为用户 MIDI、谱面、设置与练习历史，迁移需可恢复。

音频实时路径不承担文件解析、制谱、网络与持久化。生成任务在后台执行，支持进度和取消。每轮集中完成一批代码改造；只执行受影响编译和必要关键行为 / 小范围界面检查。里程碑再打包，禁止用真实用户资料测试，未经要求不推送。
