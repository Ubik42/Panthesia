## A01 应用与设备边界

当前新版使用 React＋TypeScript、Tauri 2 和 Rust。浏览器开发入口通过本机 HTTP 调用同一引擎；旧原生 WGPU 入口仍保留。Verovio WASM、PDF.js、外部 MuseScore/Audiveris 和音源插件各有适配路径。应用业务主要由 Rust 与 TypeScript 维护。

播放时间、MIDI 调度、评分、曲目身份与持久化由 Rust 负责。前端负责展示、输入和编辑草稿。渲染器或特效读取音乐事实，新的判定规则进入音乐领域或应用服务层。

目标依赖方向：界面/传输 → 应用服务 → 音乐领域；应用服务通过接口调用设备和存储。当前 `panthesia-core` 默认构建不包含图形或音频设备；旧原生图形显式启用 `native-render`，VST3 通过独立设备适配 crate 接入。crate 数量和目录整齐程度仅作为维护手段。

## A02 状态和协议

| 状态 | 归属 | 更新原则 |
| --- | --- | --- |
| 播放位置、按键、即时判定 | 引擎＋播放订阅 | 控制更新范围；业务页面按所需版本读取 |
| 曲库、历史、谱面列表 | 对应业务读取层 | 按引擎连接和资料版本废弃过期回复 |

当前已有生成命令与若干领域协议；响应和外部工具结果仍有未完全类型化的部分。优先为交付流程建立明确的成功、失败、过期和可恢复结果，按修改范围逐步补齐。前后端传输使用同一契约，解析失败在接口边界报告。

## A03 播放与后台执行

当前已有控制通道、后台任务池、异步加载、设备读取、保存和恢复模块。命令处理仍需按执行成本检查。

目标：播放运行时接收短控制和已准备好的不可变结果；解析、索引、外部工具、复杂推荐及大对象处理在后台。结果应用前核对曲目内容、资料版本和请求归属。取消须区分准备、计算和提交阶段；已经提交的操作读取实际回执后显示结果。

评估采用具体输入规模、暂停/止音响应和实际操作记录。发现新的阻塞路径时登记明确问题，再修改该路径。

## A04 音乐对象与资料身份

目标关系：

```text
作品（标题、作曲者、作品号等描述；可有多个演奏与谱本）
├─ 演奏版本（MIDI 内容身份、原始时序、来源）
│  ├─ 文件位置（同内容可多路径）
│  └─ 练习配置与历史（范围、网格、手别、模式、当时条件）
├─ 乐谱版本（来源内容身份、校对状态、编辑关系）
│  ├─ 原始 MusicXML/MXL
│  └─ PDF/图片与批注
└─ 关联（演奏与谱面映射、置信度、缺失和冲突）
```

当前已有内容身份、文件位置、谱面版本、原谱登记、个人标记和历史条件。作品与多个演奏的关系已由 `repertoire.json` 登记，并在曲库详情中管理。标题相同只提供候选关系，采用时仍需确认版本。

规则：移动路径保留内容身份；改变内容形成新版本；历史保存当时条件；迁移个人标记前核对来源与映射。迁移出现歧义时保留旧资料与待确认状态。实现和迁移证据见 R2-01；谱面内容变化后保留旧版本并重置受影响的校对状态。

## A05 乐谱四层与标准

| 层 | 保存或表达的内容 | 当前实现与缺口 |
| --- | --- | --- |
| 文档/来源 | 原字节、格式、来源、版本、原有音乐与排版信息 | `notation.rs::ScoreAsset` 保存 bytes 和来源指纹；完整可编辑文档层待定义 |
| 练习语义 | 分数拍位、音高拼写、声部、谱表、支持的指法/踏板/反复等 | `musicxml.rs::Score`、`Part`、`Measure`、`ScoreEvent`；范围有限 |
| 演奏与对应 | 原 MIDI 时间、实际击键、反复出现、书面与演奏映射 | 演奏生成、scoreMap、alignment 与 occurrence 模型已有 |
| 显示 | 页面、SVG 元素、纸谱坐标、可视范围 | Web Verovio worker 和纸谱阅读器；显示映射须核对版本 |

当前 Web 的实际路径：

```text
保存的 MusicXML/MXL 字节 ──→ Verovio WASM ──→ SVG 与渲染音符证据
          │                                      │
          └─→ Rust Score ──→ 练习分析/演奏/对齐 ──→ 定位与跟随
保存的 PDF/图片 ──→ 阅读器、人工映射或经核对的自动映射
```

`public/verovio/worker.mjs` 直接调用 `loadData` / `loadZipDataBuffer`。Rust Score 是应用自建练习模型；当前没有独立实现或社区采用的证据。MusicXML/MXL 继续承担主要交换入口，MEI 作为语义和 Verovio 参考。完整 MEI 接入作为单独评估项。

模型仍有明确缺口：`transpose` 与 `wedge` 有未表达诊断；符杠、符干、歌词、完整排版等不能仅凭该模型重建。现有整数升降表达也限制更广音高系统。后续字段扩展由具体练习需求驱动。

## A06 导入、编辑、导出与稳定身份

资料优先顺序：同曲同版本的可靠原谱 → 人工核对的转换谱 → 自动初稿。MIDI 生成谱和 PDF/图片识谱均需要核对拍号、弱起、声部、分手和节奏。原始演奏中的速度变化另行保留。

原文件保持可恢复；标准化结果和个人修改另存或通过受控流程提交。当前 `score_export.rs` 在来源文档上应用个人标记，`score-timewise` 会先形成处理副本。本批已有 12 份固定谱例的一处指法往返；运行时额外核对受支持的音乐语义。未知记谱内容仍由来源保存，不能据此声明完整编辑兼容。

身份约定：

- 固定来源版本内，声部/小节/事件序号可确定性定位。
- 反复使用 source ID＋occurrence ID 表示每次演奏。
- 插入小节、重排声部或替换原谱后重新建立映射；旧序号相同只能作为候选证据。
- 渲染元素 ID 归显示适配器；逐音指法和历史依赖核对后的音乐身份。

兼容声明分别回答五个问题：能否显示、分析、播放、编辑、导出。已支持字段、未处理内容、转换诊断和资料损失应可检查。验证重点为固定样例的“导入→修改一处指法→导出→重开”，核对未修改的音乐和未知内容；随后扩展真实导出器样例。

## A07 曲库与视觉

曲库分为源码内清单/脚本/少量审定示例、独立精选素材包、用户本地扩展库。来源信息包括作者/贡献者、原链接、许可、修改和校对状态。完整数据集继续放在 `D:\Music\MIDI\PracticeLibrary` 等外部目录。素材包发布依据实际逐曲记录。

视觉分练习与演出两套目标。练习优先清楚读谱和击键反馈；演出允许更强粒子、拖尾与发光。当前 Canvas 2D 保留，先定义只读音乐事件和时间接口，再按效果及性能需要选择渲染方案。

效果状态随暂停、跳转、循环、换曲和减少动画设置正确清理。评分与设备输出由引擎继续负责。MIDIVisualizer、Notefall、Piano VFX 的具体可借鉴项与许可证记录见研讨复核；依赖引入另作实现决策。


## A08 主音量、即时命令与插件资料归属

主音量是输出状态，不改变演奏 MIDI、练习派生身份、击键力度或插件预设参数。内置音源沿用 Audio 增益；VST3 在后端音频块输出后应用增益，5 ms 按帧线性过渡、声道同步，仅使用原子参数与预先建立的状态。输出电平取增益之后的样本。MIDI 路由维护每通道原始 CC11 表情值并乘主音量，保留 CC7 / 音符力度，控制器复位后重新应用主音量；所选设备实际控制器能力另作边界。

Play / 文件编辑的全局 busy 通道不再承载音量、速度、模式和时间线定位。PlaybackAdjustmentQueue 串行发送，同类待处理指令采用最后一次值，为每个调用完成应答；来源变化及取消使旧结果失效。接口沿用 engine / content / scoreRevision 约束，文件操作并发时仍由引擎核对真实来源。

VST3Backend 由 Sound Owner 显式获得 data/vst3-state；目录来自引擎组合根已经锁定的资料位置。主桌面所有音源连接、重新选设备和重启都使用此路径。新目标缺失时只复制当前运行目录中的旧状态，新资料优先，旧文件保留。更新状态前将旧字节写入 .previous.bin，备份失败则不覆盖；读取容量为 16 MiB。插件报告恢复失败时保留原文件并停用本次自动覆盖，设置页报告恢复状态。

旧 CWD 路径只承担一次导入来源，以及尚未接入新桌面资料根的旧原生 GUI 默认构造。退出条件：旧调用方迁入显式状态目录或随旧 GUI 退出后，移除该默认写入路径；当前桌面不再向运行目录写插件状态。

## A09 演奏组合视图与共用区间查询

谱面、瀑布及琴键是同一演奏会话的展示，不建立新的歌曲或练习身份。PracticeStage 只负责排列、比例和分隔条；两种视图继续消费同一 PlaybackStore 和 PracticeRange。单独谱面 / 组合视图切换保留谱面组件及映射，隐藏的瀑布与读数停止挂载。比例拖动先在本地显示，释放时进入已有偏好事务；视图、排列、比例随布局和备份保存，旧记录补默认值。

IntervalTimeline 提供与坐标单位无关的静态区间查询。瀑布按 tick 查询，谱面按有效演奏秒数查询，均保留跨越后续起音的长音及闭区间端点。谱面跟随只滚动自己的阅读区域，不移动应用时间线；缩放后将当前音符放回阅读窗口，演奏时钟和引擎位置不变。Verovio 排版缓存及映射身份规则继续生效。

## A10 时间线旁的练习段入口

快捷选段栏复用 PassageCatalog、SaveTickPassage 和 OpenPassage，不建立第二份段落文件。A/B 的有效演奏秒数按当前速度图转为 MIDI tick，后端继续核对内容身份、网格和范围；保存同时记录现有速度与 SessionSettings。打开使用保存的练习设置，界面提前显示 BPM 与模式。

界面选项按演奏内容保留，目录读取与操作仍绑定引擎 / 内容 / 演奏及标注版本。版本变化使旧目录暂不可操作，待当前目录返回后继续；晚到的旧读取不覆盖新来源。保存回执与刷新分别处理，已提交后只重试刷新。段落条件快照、跨条件打开与旧记录补齐由 A11 接入统一核心；实际范围仍在恢复条件后由后端核对。

## A11 已保存段落复用歌曲核心的 PracticeEdition

PassagePreset.practice 保存 core::song_project::PracticeEdition，包含源演奏身份、完整 Variant 和确定性练习身份，使用歌曲管理和演奏页同一计算规则。普通、精确、谱面、指法和纸谱保存入口都记录快照。旧记录通过已有 grid 中的 practice-v1 签名恢复转调 / 量化 / 时值，读取目录只提供投影，成功打开时补齐持久化快照；原字段与源文件继续保留。旧 / 新快照先归一为同一 PracticeEdition 再比较，保持指法和纸谱重复生成的内容判定。

打开在既有 song-switch 后台事务中准备隔离 Player，恢复有效演奏后再验证网格、谱面对应和范围。范围无效时保留当前音乐数据与练习条件，成功时一起提交偏好和 Playback。读取及失败准备不改写旧段落。手工调号只在新快照中完整记录，旧签名缺失的信息采用原默认值。

备份版本 20、曲目包版本 16 明确标识该语义，保留旧版本读取。输入快照重新计算身份并核对归属；曲目包中的范围按对应练习版本的实际时长验证。旧客户端会拒绝新版本，避免忽略练习条件。计划和速度阶梯已由 A13 接入同一 PracticeEdition。

## A12 保存段落按内容身份恢复谱面

ScoreRange 已包含原谱内容指纹、演奏顺序身份与精确范围，直接作为恢复依据。打开段落时，后台隔离 Player 先恢复 PracticeEdition，再从当前演奏登记的谱面版本及现有关联中查找相同内容身份。读取实际文件核对 BLAKE3，以原演奏解析，并在当前练习条件下核对原谱顺序和范围；核对通过后，关联、偏好与 Playback 使用既有 song-switch 事务一起发布。此前采用的其他谱面仍留在版本登记中。

同内容的多个位置可互相替代；缺失、改变或范围不一致的文件返回明确错误，当前音乐数据与练习条件保持原值。原文件不改写。当前已加载同一内容的谱面沿用内存资产；重启仍按正常关联读取核对。沿用既有 ScoreRange，未增加平行身份或提升交换格式版本。

## A13 计划与速度阶梯共用练习版本

PracticeEdition::resolve 在 core 中统一验证快照身份与所属演奏，并从旧网格签名推导缺失的变换。LadderPreset 与 RoutineItem 增加可选 practice，保留原设置、评分范围、练习目标和进度结构。当前曲目保存记录完整快照；从阶梯创建计划时复制其练习版本；历史生成项目沿用签名推导。

从命名段落创建项目，在隔离 Player 中恢复其变换、原谱和范围，再按当前条件捕获同一 RoutineItem。该过程不采用谱面到当前会话，不写偏好和谱面关联。删除原先“当前网格必须等于段落网格”的重复分支。

计划打开的预检与安装都恢复目标版本，谱面范围复用原谱内容查找。正式打开继续通过 song-switch 后台准备和事务提交；原谱关联、练习设置与 Playback 一起发布。直接阶梯开始也在现有后台入口恢复变换，再核对网格和评分范围。方案重存时比较完整练习版本，条件改变后原进度按既有规则失效。

备份版本 21 标识计划 / 阶梯快照，曲目包版本 17 标识阶梯快照。解码重新验证归属；计划内嵌阶梯必须使用同一版本。阶梯范围以相应变换后的演奏网格核对。旧格式保留读取，新字段不能借用旧版本头。

速度阶梯界面、状态、保存详情和计划来源摘要使用 BPM。基准为选段起点的原曲速度；内部阶梯比例继续保留原曲内部变速，输入按既有 1% 原速精度换算。核心的比例计算与界面的 BPM 展示分开，不将用户显示单位写入 MIDI。

## A14 演奏位置书签与 MIDI 标记

个人 Bookmark 定义位于 core::song_bookmarks，按源演奏内容身份登记到 Preferences.bookmarks；位置使用 MIDI tick。转调和量化继续使用同一 PPQ / 速度图，书签不生成另一份 MIDI，也不绑定一次临时谱页排版。不同演奏版本独立保存位置。名称、编号、数量和数值范围集中验证；写入时核对原演奏时长。

midi-file 读取 Marker 与 CuePoint，保存为共享只读数组，按 tick / 名称排序去重。练习变换保留这些标记，目录使用有效演奏速度图投影为秒；超出当前有效范围的标记保留显示并禁用定位。MIDI 文本当前按 UTF-8 容错解码并截取 80 字，旧编码的精确识别仍有限制。收藏标记生成个人书签，源 MIDI 保持原内容。

书签读写加入既有 practice_catalog 后台读写流程，只合并 bookmarks 所属集合，使用来源身份和目录版本拒绝过时写入；前端复用 useCatalogRead / usePracticeEdits，提交成功后刷新失败只重读。书签组件使用独立前缀的 React key，避免与保存段落组件的同身份键冲突。

App 继续负责快捷键、焦点和模态优先级，书签组件通过明确导航接口接收索引；默认 Alt+1–9，可在既有设置中重设。导航调用原实时 seek，循环范围复用原 Loop，进入循环外的位置先关闭循环；谱面、瀑布与琴键继续消费同一播放状态。位置条为全曲静态概览，最多抽样 100 个标记，完整目录仍可选择。

备份 22 与曲目包 18 明确携带个人书签，旧格式缺省为空；导入按原合并 / 替换规则处理，曲目包核对原演奏范围。版本 18 之前的包不描述个人书签，替换其支持的数据时保留本地书签。MIDI 标记由 MIDI 自身携带，不重复写入个人书签。

## A15 普通循环重开与显示预览分离

loop_practice 从主 tick 收拢普通轮次收尾和错误阈值判断。阈值是用户资料目录中的全局练习辅助偏好，0 关闭、1–100 有效，复用 practice_catalog 的后台设置准备和所属字段合并；Snapshot 从偏好投影该值，避免另存重复状态。该辅助不改变 PracticeEdition 的音乐身份；日课、阶梯、录音和聆听不应用它。

达到已判定的错音 / 漏音阈值后停止发声，冻结本轮并复用自动保存队列。失败轮使用原回放、计分和累计时间记录，PracticeSessionContext.loop_restart 保存触发阈值；正常记录缺省无此字段。保存成功后才按既有音频停止代数判断能否自动恢复；失败恢复仍走原保存重试。失败轮不增加 repetitions，不进入阶梯或自适应判断。reset 清除当前失败标记，重开次数随本次循环显示。

错误重开可作为同一任务下的失败证据，中断熟练连续次数；不会作为达标证据或完整演奏周证据，不作为普通完成轮次的逐次同条件比较；历史总览仍保留实际失败记录。备份版本 23 保留这项结果语义，校验阈值范围；旧记录及未包含新结果的旧备份继续读取。

下一轮预览属于 display.loopPreview，默认开启，随界面偏好和显示备份保存。Piano 将当前循环窗口和一轮源窗口映射到相邻 tick 空间，复用 NoteTimeline 区间查询和源小节网格；超出当前循环的后续歌曲音符不代替下一轮。淡色音符不加入键盘高亮、击键效果、选择命中或引擎事件。开关不改播放位置、状态或 noteEpoch，真实跳转继续由引擎执行。

现有正常轮次的末尾判定等待与保存后再继续仍在；本批没有用显示时钟隐藏该延迟。下一批应集中检查并改造该实时 / 保存边界及长曲显示性能。原生检查同时隔离引擎资料根与 WebView2 用户目录，使用 Microsoft 文档支持的 [WEBVIEW2_USER_DATA_FOLDER](https://learn.microsoft.com/en-us/microsoft-edge/webview2/reference/win32/webview2-idl?view=webview2-1.0.3967.48) 覆盖，避免检查操作写入日常界面配置。
