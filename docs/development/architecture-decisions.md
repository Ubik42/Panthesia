# 当前架构决策

更新：2026-11-20。当前决策替代旧控制性架构文字；旧 ADR 快照位于 archive/2026-11-20/architecture-decisions.md。

## A01 产品壳与后台能力

前端按 Synthesia 截图和官方流程组织页面；前台只表达用户正在选曲、设置、看谱和弹奏需要的对象。DuET、音频处理、目录索引、转调量化、谱面准备和迁移作为应用服务运行。复杂算法、模型路径、任务回执和存储细节进入后台或按需设置。

## A02 目标依赖关系

```text
Screens / screen controllers
  → Application facade / typed queries and commands
    → SongRepository | PlaybackSession | ScoreService | JobService
      → Music domain + ports
        ← storage / filesystem / MIDI / audio / VST3 / model-process adapters
```

| 边界 | 拥有的内容 | 不应承担的内容 |
| --- | --- | --- |
| Music domain | 身份类型、时间轴、音符、手别、变换和谱面关系 | Tauri、设备句柄、文件对话框、窗口状态 |
| SongRepository | 歌曲/版本/位置/标注的事务、迁移、查询 | 播放时钟与前端组件 |
| PlaybackSession | 播放事实、事件游标、等待键、模式、seek/loop/stop | 全库扫描、制谱、磁盘写入和评分 |
| ScoreService | 解析、页/范围缓存、对齐、采用谱面 | 音频线程和业务导航 |
| JobService | 任务身份、进度、取消、超时、失败回执与旧结果拒绝 | 给每个任务增加常驻前台卡片 |
| Device adapters | MIDI 输入输出、SF2、Pianoteq、设备重连 | 歌曲归属、谱面选择或练习评分 |
| Desktop shell | 原生文件入口、窗口/生命周期、进程适配 | 音乐领域与重复业务存储 |
| Screen controllers | 导航、选择、用户编辑草稿、交互命令 | 逐帧时间推进、完整乐谱重算、路径身份判断 |

这些首先是模块边界。按依赖需求抽 crate；不为目录数量建立新微服务或重复 DTO 层。

## A03 存储目标

中心目录使用 SQLite/rusqlite，由专用存储服务写入。统一歌曲关系、资产位置、版本、手别和派生任务；大文件按内容哈希放在独立资产库。数据库原子提交与文件提交日志配合：先写临时资产、核对哈希并持久化，再提交引用；失败留下可回收临时文件，不提交空引用。数据库与外部文件不是同一个原子事务，不能仅凭 SQLite 事务宣称两者同时提交。

SQLite 依据其[原子提交说明](https://www.sqlite.org/atomiccommit.html)处理关系记录；Rust 接入使用 [rusqlite](https://docs.rs/rusqlite/latest/rusqlite/)。实施时选择与当前工具链兼容的固定版本及锁文件。B01 已接入歌曲关系目录、MIDI 副本和按内容保存的 JSON 标注文档。普通文件演奏由新文档拥有手别和指法；workspace、会话设置及非文件演奏入口仍有过渡消费者，完整统一存储尚未完成。依赖锁文件中的 thiserror 升级由 rusqlite 的跨目标传递依赖要求触发。

迁移生成新目录、迁移清单和校验结果。切换后只写新存储；旧适配器提供只读导入和导出恢复。兼容不意味着同时维护两套活动核心。

## A04 音乐与实时路径

原始 MIDI 字节的 BLAKE3 身份与文件路径分离。tick 是音乐顺序的基础；tempo map 决定秒，小节由 meter map 决定；播放 BPM 是时间尺度，不改写源文件。手别和播放职责独立，等待模式只跟踪所需琴键，不计算准确率或达标。

播放载荷预先编译为不可变事件序列，切换载荷使用版本标记和有界消息。音频回调避免 I/O、分配和阻塞锁。目录、解析、模型和存储工作在后台执行；停止与止音命令有独立响应路径。

## A05 渲染与谱面

屏幕读取时间锚点推算显示时刻，音频/引擎拥有事实时钟；React 处理低频状态。瀑布通过索引查询可见区间，按可见数据绘制；不逐帧遍历全曲、序列化全谱或重建 React 树。谱面页和节拍索引由后台生成，页/范围缓存有大小上限。高级皮肤和特效通过相同渲染设置访问，不新增默认工作区。

## A06 原创替换

Neothesia 应用逻辑逐模块退出：先稳定领域协议，再以功能规格和独立实现替换消费者。已有 GPL 代码在退出前准确保留来源。midly、cpal、midir、rtrb、oxisynth、Verovio、PDF.js、SQLite 等通用依赖单独记录来源和许可；原创应用层不要求自研操作系统、标准格式解析库或音频驱动。

审计已见代码不能称为严格 clean-room 独立隔离开发。后续实现应记录真实开发来源，不作无法证明的隔离声明。最终许可结论依据实际保留内容、集成方式及来源审核。

## A07 迁移方式与退出条件

每批完成“新实现 → 消费者接入 → 必要检查 → 旧路径退出”。适配层有明确任务编号和移除条件，禁止无限保留双写/双 UI。App.tsx 退为装配和路由；Player 聚合退为应用服务协调，评分的旧可变处理器退出主线运行和写入路径，旧历史可通过独立导入兼容读取。

## A08 交付与变更范围

当前支持 Windows 桌面正式包；浏览器入口服务开发调试。旧原生跨平台、视频编码 CLI 和原 AI wrapper 不属于当前产品入口。已有九项未提交曲库调整属于本轮之前内容，独立保留。文档不能把旧版本检查、源码存在或局部截图等同于当前产品完成。

## A09 文件演奏标注与会话配置

手别与播放职责分开：SongAnnotation 文档保存轨道/逐音手别、指法、小节和谱面关联；SessionSettings 保存自动/自己弹/静音、可见性与练习方式。迁入新文件演奏后清空旧 parts，避免两处活动写入。标注文档是由 SongRepository 绑定内容身份的文件资产，经既有提交日志与设置一起发布；SQLite 不重复保存一份可独立修改的相同负载。

当前 core/library 提供旧接口的窄路由：只有完整 library/assets/midi 或 library/assets/exercises 的受管理布局会进入新文档适配器，外部文件不会仅因名字是哈希而匹配。内置模板、生成练习和曲目包已接入，旧元数据与位置兼容入口仍需收束；旧 core 的来源替换任务继续执行。轨道编辑从普通命令和演奏调节入口统一进入后台事务，避免新持久化操作落在播放线程。

## A10 持有谱面与可移植演奏

MIDI 与 MusicXML 按内容保存不可变字节，关系文档和用户命名可单独更新。原路径丢失时按内容恢复到已持有资产；占用资产内容变化时保留该文件并另存完整副本。启动恢复和生成练习的迁移在准备工作线程完成，运行时接收已读资产和观察记录。

曲目包第 20 版将原始 MIDI 和练习变换分开保存，并携带稳定音符身份与未应用原行，恢复后可返回原调与原始时值。旧格式经版本检查导入。新导入在提交文件事务后登记中心曲库；登记失败只生成一条后台待恢复提示，已保存的演奏继续可用。完整歌曲使用 panthesia-song 外层归档组合全部演奏包。它复用单演奏的校验与恢复，单次提交文件，再经持久回执发布歌曲关系；关系发布由 song_repository/archive 模块负责，重启后可幂等继续。不同演奏的谱面身份和校对决定通过稳定身份与恢复版本关联，刷新目录后继续有效。

## A11 兼容入口与中心状态

兼容命令读取和修改同一份内容标注，原路径仍可承接旧修改历史。目录缓存、外部旧附件和旧 repertoire 只提供来源及投影；已有内容标注作为当前状态。字节身份验证在后台进行，已通过且文件时间戳未变的结果可以缓存；实际音乐加载仍核对所选内容。导入和重定位由后台事务发布，界面不直接复制旧附件。

存量迁移使用只读清单、独占资料锁、冷快照、逐内容文件事务和完整回执。源 MIDI/谱面与旧附件不改写，无法匹配的身份和设置保留并单独记录；不从曲名或近似音高推断同一内容。该处理关闭 B01 的数据归属与迁移任务，B02 已由 c706a2d 接入原创解析/时间/布局实现。

## A12 源音符与视图索引

panthesia-music 的 tick-native 源演奏保持原字节身份，NoteId 按原物理轨与正力度 NoteOn 序号建立。视图索引、转调后音高和秒数均为投影。持久标注通过源身份恢复，旧 release-order 索引只有确定映射时应用；未知行连同原因进入 unmapped，并随曲目包保存。兼容视图用于既有消费者，随后在 PlaybackSession/屏幕与旧 core 拆分时逐步退出，禁止回到音高+时间作为唯一身份。详见 [音乐领域协议](music-domain.md)。

## A13 前台页面与声部分手提交

fb37bd7：useProductScreens 拥有主页/设置与歌曲设置/声部/分手/演奏/自由演奏的呈现状态，既有 WorkspaceNavigation 暂时承担准备与锁保护。二者是职责明确的过渡适配，P11 继续统一导航准备与编辑会话。选曲页保持同一实例；隐藏演奏页不运行昂贵的琴键/谱面组件。旧主检查栏从产品 JSX 退出，变换和版本设置从“歌曲选项”按需进入。

SetPartHands 绑定 contentId、轨号和手别 proof，在 practice_edit 的 Hands 事务中构造整首分手并合并稀疏修正；不会把全曲音符作为巨大前端请求传入。整轨手别选择明确替换该轨的旧逐音覆盖，其他轨与指法保留。变换只改变视图，分手仍按源身份保存；无效 proof 在写入前拒绝。普通播放控制不进入该工作。

## A14 声部设置与标签呈现

usePartSettings 拥有声部选择、异步保存、拖动复制与预听租期；useProductNavigation 将引擎切换与页面切换组织为单个受保护操作。连续声部编辑从当前已绑定会话取得修订，contentId/engineId 必须仍与编辑来源一致；分手/恢复默认额外核对 proof。TrackAppearance 通过 practice_edit 的 Preferences 路径保存；颜色/显示选择按 left/right/other 存在现有外观设置中，并随曲目包往返。ResetPartSettings 在同一后台文件事务中恢复当前轨默认手别/外观/声音与逐音播放规则，指法和其他轨不受影响。

乐器预听使用已有独立试听调度器的短内存乐句，循环由引擎驱动；前端只续租、停止和换音色。关闭/失焦/丢失租期及实际输入会停止预听，演奏位置、录音、用户 MIDI 计数与判定均不接收预听音符。琴键/音符标签分别持久化，所有权来自实际手别和播放方式；调性使用 effectiveTonic/effectiveFifths，与原始 tonic 分开，避免转调后仍显示原调唱名。

## A15 页面协调与源绑定编辑会话

6082c0f：产品导航拥有切换准备、页面和止音；usePlaybackActions 拥有普通/实时合并命令，usePerformanceKeyboard 拥有快捷键代次和虚拟按键释放。useSongEditors 按 engineId/contentId 绑定编辑栈，来源变化即退出可见编辑；草稿仍由各数据存储持有。SongEditorHost 只呈现顶部编辑器。谱面配对在选择和读取后核对同一来源。

workNavigation 将后台回执映射到既有产品页面/编辑器，准备后再核对内容与取消信号；旧评分任务不能进入普通练习。LibraryOpening 在已绑定来源后选择歌曲设置或演奏页。旧抽屉和工作区导航控件退役，底层兼容资料仍按 P20 来源台账处理。资源管理器定位对失效原路径先解析持有资产，磁盘工作留在后台线程。

## A16 实时会话、音乐游标与绘制缓存

db70b6a、f5a4e4c：PlaybackSession 拥有时钟、事件/等待目标游标、所需琴键与节拍边界；只接收内存时间线和只读角色投影。playback_adapter 连接 MIDI 格式、当前声部与音源输出，Actor 持有统一会话。暂停/定位/换曲/退出仍共用 panic 的停止代次，陈旧输出包由 sound_runtime 的代次检查丢弃。Mode、Wait 与手别切换保持当前位置、事件进度和运行/暂停状态，清理旧选择的等待目标；seek 与循环才重建游标。

Driver 每次 tick 直接推进内存会话，退出旧 pending_save::tick 捕获包装；资料变更仍由命令/后台事务捕获并确认。预备拍、普通节拍器和状态投影共用 musical_position；普通播放按拍边界触发一次，迟到时不补发一串旧拍。预备拍不再每次克隆完整状态。常规播放 MIDI 包使用栈数组。

瀑布延续可见区间索引。高度不超过 512 像素的音符缓存完整形状，每次一张图片；更长音符用固定纹理分段绘制。音符缓存继续限制为 8 MiB / 128 项。琴键静态标签按来源、当前模式/手别、布局与显示偏好失效；动态指法另建当前帧映射。界面结构与配色保持既定规范。

## A17 谱面页面与排版租期

2331d0c、0fe4dc5：页源按内容/布局身份共享，准备前取得租期，当前页通过带请求身份的 worker RPC 加载。SVG 使用 32 MiB / 16 页 LRU；索引读取 MEI，最后一个读者退出时中止并释放排版线程。纸谱仅按需取得页面并保存准备图像；切源/取消拒绝过期结果。WASM 整曲布局及整曲映射仍是 P15 待替换路径。

## A18 实际音高与书写符号

63cd930：源 MusicXML 的 alter 表示实际升降，accidental 表示书写符号；依据 [W3C alter](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/alter/) 与 [W3C accidental](https://www.w3.org/2021/06/musicxml40/musicxml-reference/elements/accidental/)。当前 Verovio 导入的丢音高情况在渲染副本中通过 accid.ges 修正，按稳定渲染 ID 关联，原谱及已写符号不改。当前修正覆盖现有核心支持的整数 -2..2 升降。生成谱 v3 另外按调号、小节和声部维护书写状态，生成必要的还原/升降号。压缩输入通过共享有界解码接口读取。

## A19 练习谱范围与来源证明

1fecbbb、ecab0b1：ScoreView 读取请求携带演奏身份/谱面修订，MIDI 简化谱及量化谱一次准备 32 个全局小节。生成器 v4 的片段 ID 由源轨、音符索引和全局书面位置组成，窗口重叠时可复用；持久源 NoteId 保持。范围开头恢复谱表、调号、拍号与当前速度，边界连音保留；已有手别优先。映射在后台重建同一窗口并核对显示字节指纹，回执哈希加入小节范围，陈旧版本/范围不安装。Driver 只取得共享源、配置和变换快照，调性估计留给后台。外部原谱的整曲布局和映射仍是 P15 待替换路径。

## A20 启动恢复的注册表发布

8547393、688df52：启动恢复可重新关联持有谱面版本的位置。发布前比较原注册表与磁盘当前值，通过既有 asset_storage 恢复日志提交，再安装对应内存快照；提交失败阻止安装不一致状态，失败/跳过准备使用原注册表。用户外部修改受到观察值检查保护，源资产不因显示或恢复而重写。
