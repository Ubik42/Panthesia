# 歌曲核心与派生关系

更新：2026-11-19。本轮实施，后续迁移按 modernization-roadmap.md。

## 关系与归属

| 对象 | 身份 | 存储与用途 |
| --- | --- | --- |
| 作品 MusicalWork | work ID | 已有 repertoire 登记，关联多份演奏 |
| 演奏 PerformanceEdition | 原始文件内容 ID | 多个文件位置属于同一内容，原始时序独立保存 |
| 练习 PracticeEdition | 源演奏 ID + Variant 参数的版本化哈希 | 转调、网格量化、时值和调性参数，按需派生，无需维护 C 调 / 量化 MIDI 副本 |
| 谱面 NotationEdition | 演奏 ID + 谱面版本 ID | MusicXML/MXL 内容、文件位置、质量和采用状态 |
| 生成 NotationGeneration | 源内容 + 生成器实现身份 + 生成参数 | DuET 完整输出和来源；谱面版本引用生成记录 |

SongProject 是对现有持久记录的共享读取投影。管理与谱面工作区已接入；运行时已使用同一 Variant 及 PracticeEdition 身份算法。当前持久化仍沿用 repertoire、web-preferences、曲目 sidecar 和 notation-drafts。后续切换主流程时逐一替换旧拼接适配，避免增加第二套登记。

采用状态以具体谱面版本 ID 为准。同内容、不同位置或用途的两个谱面版本可分别登记，不能仅用内容哈希标记两者同时采用。

## DuET 生产链

当前歌曲原始 MIDI → 校验内容身份 → 本机 DuET 后台任务 → 原演奏副本及模型输出 → MusicXML 解析 → 持久初稿 → 演奏顺序预览 → 用户采用 → 注册谱面版本。

生成记录位于资料目录 notation-generations/<generation ID>；每次推理使用独立 run 子目录，成功后写 manifest。相同源内容、模型 / 实现、设备设置和标题复用已完成的 MusicXML，并核对内容哈希。生成身份包含 DuET Python 实现、包版本、Torch 版本、模型权重与配置、软件内适配器；模型输出保留 notes.json 和 report.json。

本机运行环境按 PANTHESIA_DUET_PYTHON / PANTHESIA_DUET_MODEL、资料目录 duet-runtime.json、默认路径发现。默认使用共享 Transkun Python 环境已安装的 duet-score 和共享 DuET 权重。软件调用禁止自动下载，任务支持取消与超时，不占用音频实时线程。

duet-runtime.json 可配置 python、model、device（auto / cuda / cpu）。运行环境设置 UI 已接入“演奏与制谱设置 → DuET 制谱”，谱面管理的添加与初稿页可以直接进入，关闭设置后返回原处。duet_runtime 模块统一负责配置读取、有效路径解析、文件状态与检查，生成任务消费同一解析结果；环境变量优先级不变，界面列出实际生效来源。

环境检查在后台本机 Python 中导入 DuET 与 Torch、读取模型配置及 CUDA 状态，不进行推理或下载。保存核对原配置版本，原字节备份到 settings-backups/duet-runtime-<内容哈希>.json 后原子替换。未保存输入在本次软件会话中暂存；恢复自动查找也需要保存。实际关闭并重启软件后，已保存设置仍可读取。既有 CUDA 制谱证据继续有效，本轮额外核对 CPU 环境检查与设备选择。环境安装向导和跨机器发行依赖仍需后续处理。

## 记谱规范及后续迁移

MusicXML 是主要乐谱交换格式；原始 MIDI 提供演奏时序。Verovio 显示谱面，MuseScore 用于编辑和 PDF。ABC 后续按实际用途提供适配，不作为第三套音乐核心。

DuET 从原始演奏推断乐谱，练习量化和转调作为独立参数。practice_score 按转调参数生成显示副本，更新音符、八度、分声部 / 谱表调号、和弦根音与低音、常见装饰音升降记号；原 MusicXML 与谱面内容身份继续指向源文件。按调号确定全曲音程拼写，八度转调保持原调号；原谱映射时还原渲染音高，再用原音符身份取得当前练习时序。

启用量化后，practice_engraving 从有效 MIDI 生成临时 MusicXML 练习谱，含双谱表、和弦、重叠声部、附点、休止、跨小节延音、拍号变化和不完整小节。源演奏音轨 / 音符索引在练习变换中保持稳定，谱面片段 ID 直接对应该身份；跟随时间取当前片段拍位。临时谱身份为 PracticeEdition + 记谱器版本，另有显示文档内容指纹；不登记成一份新的原始谱面，也不修改 DuET 初稿。

有原谱时可在“量化练习谱 / 所选原谱”间切换；没有关联 MusicXML 时，也可直接生成量化练习谱。转回原始时序后恢复原谱或 MIDI 即时谱。量化谱按音区分配上下谱表，书面精度为 1/128；关闭时值量化时，实际发声继续使用有效 MIDI 的原时值。复杂分手、自动符杠及完整编辑继续由 DuET / MuseScore 负责。非传统调号、微分音装饰记号仍有明确限制；移调显示不复用原调吉他指板图。

未量化的纯 MIDI 目前仍进入 MidiPracticeScore。后续统一未量化简化记谱策略后，使用同一核心记谱与 Verovio 路径替换该浏览器绘制器；旧组件随这条路径退出。量化谱已有独立音符身份，后续高级选段应接入通用练习范围，避免重新借用原谱事件编号。

后台 Playback 发布包包含当前有效演奏和 source_file，两者必须一起切换。ScoreVersions 为纯读取；当前关联谱在切换 / 解除关联事务中登记，关联谱 ID 由内容及规范化位置决定。读取、预览与登记使用同一算法，避免读取触发写入及切换后旧谱面无法选回。

## DuET 逐音来源协议

worker 对照 DuET 官方 MIDI 读取结果验证输入顺序和时序，记谱时记录实际使用的 input_id。每个写出的有音高音符使用 MusicXML 的 note@id：panthesia1-源内容ID-音轨-源音符索引-音高-起音微秒-结束微秒-input_id-谱面片段序号。延音拆分后的片段各有唯一谱面 ID，引用同一源音符；input-identity.json 保存完整输入记录，原 notes.json 继续保存模型输出。

engine::duet_alignment 对照原始 MIDI 核验内容身份、事件索引、音高与起止时间，建立 ScoreEventId 到 MidiNoteId 的关系。来源确定度不等同于节奏 / 分手质量；记录真实时差，自动谱面保持 automaticDraft。来源缺失或核验不符时转回已有匹配流程，旧谱面继续可用。

Verovio 保留 note@id；引擎按已验证的谱面 ID 直接连接对应关系，取当前有效演奏的时间进行高亮、定位与跟随。此路径无需重解码渲染 MIDI 并按时间猜测对应，普通外部谱继续通过原适配。

来源采集依赖当前 DuET readable writer 的 pitch_el / Speller 调用约定，边界隔离在独立 Python worker。输入顺序、写出音符数量和每个音高均核验；接口变化会停止本次生成。实现与适配器内容哈希已进入生成身份。后续 DuET 提供公开来源导出接口时替换此处。

同歌关系通过已有 repertoire 的 work_id 维护。归组仅改变所属作品，拆分优先复用该演奏原有的未占用独立身份和资料，保持谱面、设置及历史归属各自演奏。

## 谱面显示缓存

scoreRenderCache 只缓存清理后的 SVG 页、渲染 MIDI 和逐音渲染证据。以实际显示字节的 SHA-256、压缩格式和排版规则版本为键，避免原谱指纹相同但转调 / 量化显示不同的内容误复用。最多保留三份、估算 32 MiB 的结果，按最近使用淘汰，关闭软件即释放；大谱仍可显示，但超过预算时不进入缓存。

缓存不包含引擎映射令牌。每次打开仍按当前演奏内容、scoreRevision、来源指纹和逐音证据调用引擎对应；换连接、换版本或改练习条件不会沿用旧映射授权。读取、排版和对应继续分别处理，卸载视图时中止未完成的排版并释放 worker；再次打开已完成的相同内容复用排版结果。修改 Verovio 排版选项或输出规则时同步升级缓存版本。

## 当前演奏的临时范围

练习范围继续使用引擎 Snapshot.passage 的绝对秒数定义。usePracticeRange 只维护界面草稿：来源为 engine ID、演奏内容 ID 与 scoreRevision，两个端点来自有效演奏的音符起止时间或当前位置。只有提交循环后，引擎 passage 才成为实际练习范围；切歌、换谱或练习变换改变上下文时清理旧草稿。

MIDI 即时谱、已对应的 MusicXML 与瀑布通过同一有效 MIDI 音符身份选范围。两次点选包含首尾音符，可跨视图完成；时间线集中设置 A / B、启用和退出循环。谱面已有的精细原谱选段继续使用原谱顺序与事件身份，临时范围不新增一套谱面版本或持久登记。量化谱从有效 MIDI 直接对应，不借用原谱小节编号。

循环中的局部时间线显示精细位置，另用全曲概览显示范围所处位置。短于十秒的窗口显示百分之一秒，刻度不因取整而重复。正在播放或暂停时改变循环范围会保持相应状态；退出循环保持当前位置。边界、录音、完整演奏与计划约束继续由现有引擎命令处理。

## 曲库读取与选择

songCatalog 是 core::song_catalog 的轻量查询：每份演奏返回内容身份、所属歌曲、歌曲标题 / 作者、版本名和已登记谱面数。查询在后台合并持久关系与扫描器已核对的曲目快照，不写分组文件，也不验证 / 解码 MusicXML。扫描器快照通过弱引用接入 Engine，目录数据只有原有提供者一份。

曲库以 work_id 生成歌曲行，以内容 ID 生成演奏版本，同内容的多个位置作为版本的位置选择；标题仅用于显示和搜索。过滤保持目录范围，选定歌曲后可查看其在整个当前曲库中的演奏版本。收藏和最近记录以内容 ID 查询，已有明确身份的文件不继承同路径另一内容的记录。

浏览器按歌曲分页，分组、内容查找、位置查找与统计使用缓存索引。目录连续更新时，轻量关系查询合并到短暂静止后执行。选择某个演奏或位置会直接打开对应文件，并继续使用引擎原有内容核验。

演奏版本管理组件被演奏页和曲库共用。演奏页恢复可见时重读歌曲关系，避免曲库编辑完成后继续显示旧版本；隐藏期间暂停这项查询。

本轮没有迁移或覆盖用户源文件。后续涉及存储替换时，提供可恢复迁移和明确旧适配退出条件。
