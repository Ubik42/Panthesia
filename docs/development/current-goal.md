## 每轮工作

1. 所有工程命令显式以 D:\Music\_tools\Panthesia 为工作目录。先读 docs/development/goal-state.json、docs/development/current-plan.md 的活动批次和 docs/development/modernization-handoff.md 最新记录，再看 Git 状态。原九项曲库路径调整已并入 c7ecdee；以当前 Git 状态识别新增改动，禁止覆盖他人工作，同一文件允许继续重构。
2. 检查两小时方向审核是否到期。未到期则直接开发，不重复整库审计、重做已通过检查或重新论证架构。
3. 每轮集中完成一批关联任务，默认安排至少约三十分钟的真实调查、实现、接入和必要核查；以完整使用流程为单位，不把拆一个文件或修一个按钮当成交付。达到清楚的完成条件可直接收尾，不等待凑时长。
4. 允许重构、替换、删除已退役实现和迁移目录。需要保护的是用户 MIDI、谱面、标注、设置和录音；旧架构、旧组件和旧文件名不是固定约束。
5. 新实现接入后同步退出旧路径；临时兼容层必须标明任务和退出条件。禁止为了保留所有旧模块而让同一职责长期多套并行。
6. 每批更新实际状态、提交、证据和下一入口；报告源码改动、必要检查、实际运行与运行包四种状态。剩余项如实留在计划，不用局部实现、旧版本或截图冒充总体完成。

## 固定产品边界

- Synthesia 官方截图与操作为前端依据；先确认页面对应图，再实现控件位置、层级、空间和返回。自有 Panthesia 品牌、简体中文与自有/许可明确素材。
- 继续执行明确差异：BPM 为主要速度单位；删除“全部歌曲”“入门练习”、八秒试听和常驻预览侧栏；文件操作放右键。算法、版本、模型、路径和诊断不挤占演奏舞台。
- 连续播放不依赖用户按键发声；等待模式只等所需琴键。评分、准确率、达标、日课、表现目标与晋级只在 feature/assessment-lab，不作为普通练习的前置条件或可选开关。
- DuET、音频转谱、转调量化、谱面准备、目录扫描和迁移在后台。UI 只在既定入口展示必要状态、结果或采用操作。
- 音频回调与时钟不执行目录扫描、模型推理、磁盘持久化或阻塞 UI 工作。瀑布按可见区间渲染，谱面按范围/分页加载。
- 对歌曲、资产、演奏版本、手别、练习变换与谱面建立统一归属；原始文件和旧数据有可恢复迁移。先解决 Look at the Sky 的旧路径和版本归并，再扩展边缘能力。
- 原创替换依据具体实现和来源清单，第三方通用库按许可使用。旧版权通知不通过改名删除；不宣称已经完成无依据的从零原创或 clean-room 重写。

## 每两小时主动检查方向

执行 scripts/review-goal-direction.py --status 读取到期时间。使用 UTC 时间戳；goal-state.json 保存 lastDirectionReviewAt、nextDirectionReviewAt 和 goalPromptSha256。执行文件内容变化也立即触发一次复核。累计开发中每满两小时，在最近安全批次边界主动检查，通常在到期后十分钟内完成；若单一构建仍运行，则先继续观察同一进程，结束后立即检查。

检查五项：本批是否推动 B00–B07；前端是否对应 Synthesia 参考；扩展是否回到后台/按需设置；是否又引入评分/元数据等边缘主线；是否真正替换旧实现、保护数据并缩小已知交付缺口。同时检查是否把大量时间花在重复测试、归档和汇报上。

发现偏移先停止该偏移子任务，保留可恢复代码，调整回当前批次。目标内的顺序、兼容策略或实现办法可直接调整 current-plan.md；必要时更新本 Goal 文件、版本及变更理由。固定产品边界和用户要求不得由自检擅自改写；新增目标需要用户明确指令。

审核结论用 --record aligned 或 --record adjusted 及 --summary（Windows 中文可使用 UTF-8 的 --summary-file）、--evidence 写入检查点与 direction-reviews.jsonl。记录实际时间、差距、纠正动作和是否更新 Goal。连续空闲期间不安排自动桌面提醒；恢复开发后若到期，先做一次检查，不补跑所有错过的时间点。不要创建追踪本任务里程碑的自动化。

Goal 工具中的总目标维持稳定，并引用本文件。工具没有修改活动 objective 的接口时，通过更新本执行文件和检查点完成提示词调整，不为更换提示词把未完成目标标为完成。

## 少测试与有效交付

主要时间用于真实实现和接入。纯文档只做链接/事实核对；入口和依赖调整用 Cargo metadata；实际行为改变只选直接覆盖风险的编译或定向操作。一次相关检查通过后，只有新增改动、失败或未解决风险才重跑。数据迁移、实时止音和文件完整性必须做必要核对；其余不建立完整回归门禁。

旧评分测试不成为当前主线门禁。不新增只镜像实现的测试或为美化、移动文件写成套用例。构建和打包集中在形成可使用里程碑时；不因每次文档修改重编完整桌面或重跑浏览器。遇到失败先查原因，避免无变化地重复整套命令。证据已足够时继续实现。
