# 原创 Panthesia 开发计划

版本：2026-11-20 / 4。按用户最新指令推进；工具长期 Goal 已清除，本文件继续作为工程任务队列。本文件是唯一任务队列；旧勾选和旧发布说明不用于推导完成比例。

## 交付目标

原创应用实现，主界面与交互逐屏复刻 Synthesia。歌曲管理、演奏和声音可靠；DuET、转调量化、谱面准备及音频处理作为后台能力，通过既定设置入口访问。Windows 桌面版为当前交付平台。第三方通用库按许可使用；Neothesia 应用代码按来源台账替换或退出产品。

评分、达标与自动晋级留在独立分支。界面继续执行用户明确差异：简体中文；Panthesia 品牌；速度直接用 BPM；删除“全部歌曲”“入门练习”分类、八秒试听、常驻预览侧栏；文件位置放右键；额外功能隐藏于按需设置。

## 具体任务

### B01：让歌曲始终可用

- P01：建立 SongRepository 与资产持有策略，收束现有 repertoire、workspace、preferences 和 sidecar。SQLite 作为中心目录库，文件资产仍独立保存；事务和迁移由单一写入服务负责。
- P02：导入默认保存按字节哈希去重的演奏副本；原路径作为可变来源。外部文件移动时先使用持有副本，再后台按登记目录定位；同名文件不自动合并。
- P03：歌曲 → 演奏 → 练习变换 → 谱面关联；一首歌一行、版本按需展开。对 Look at the Sky 的五条旧记录做只读调查、迁移预览与精确关联，不以标题猜测合并。
- P04：轨道手别、逐音覆盖、指法和段落归属内容身份；既有 `.neothesia.ron` 等通过导入器读取。旧文件、设置和历史保持可回退，迁移后应用只写新存储。

### B02：替换当前使用的旧实现

- P05：在独立音乐领域模块中实现 SMF 导入包装、tempo/meter map、音轨/通道、program、踏板和 note on/off 配对。midly 作为通用格式解析库使用；不复制旧应用包装实现或仅改名。
- P06：建立明确的 tick/秒/小节换算和 NoteId 映射。旧原始字节 BLAKE3 身份保持兼容；重解析后的顺序变化必须通过映射恢复旧标注。
- P07：替换产品实际使用的 piano-layout、原计时/渲染工具；移除默认路径的 native-render 依赖。旧程序仍引用的实现列为退役模块，不进入新实现的快捷依赖。

### B03：完成界面和交互

- P08：按 UI00–UI02 实现主页、目录选曲与歌曲设置的完整返回路径；保持选中对象、滚动和搜索，后台进度不占主页。
- P09：按 UI03–UI04 实现左右手/颜色/乐器卡片、分类音色选择、自定义逐音分手；从歌曲设置进入卡片页，自定义才进入分手编辑器。
- P10：按 UI05–UI07 完成演奏工具栏、显示/缩放/标签/书签/循环弹出面板和设备/歌曲目录设置；修正“下一小节”仍带队列措辞等残留。
- P11：缩小 App.tsx 的职责，按屏幕控制器、导航、播放会话、后台任务和编辑会话拆分；删除被替代的默认界面和互相覆盖的旧样式，逐组件迁移，避免长期并排两套产品壳。

### B04：让弹奏稳定

- P12：PlaybackSession 只负责时钟、事件游标、等待按键、seek/loop 和止音；输入及音源经端口适配。暂停、切换模式、返回和退出不等待制谱或目录 I/O。
- P13：Windows MIDI、内置音源、Pianoteq 6 分别完成连接、发声、音量、踏板和设备切换；统一关闭顺序，后台日志去重，常规错误使用单条应用提示。
- P14：按时间区间索引绘制可见音符；播放事实与 React 页面状态分离；音频回调无文件访问、模型推理和锁等待。先测一段代表负载并定位瓶颈，完成一批优化后复测一次。

### B05：生成结果能直接练

- P15：MusicXML 作为交换和正式谱面格式；内部时间模型连接 MIDI 与谱面。长曲采用分页/范围加载，当前范围不因全曲容量限制被拒绝。
- P16：DuET 输入/输出、模型与参数身份、取消/超时、初稿和采用归属统一歌曲。UVR/RoFormer、Transkun 与 DuET 都在独立后台适配器中；应用不静默下载模型。
- P17：转调与量化从原始演奏按参数派生，原始表现版本始终可返回；ABC 仅为后台可生成的可选导出格式，不成为第二份手工维护的主谱数据。既有原调/C调/量化副本作为已存在的版本导入，不删除用户文件。

### B06–B07：收束与交付

- P18：按 UI08 实现自由演奏和录音流程；录音、停止、保存与重开保持连贯，支持分轨能力时按官方六轨交互组织；实际轨数限制如实显示。
- P19：后台服务和扩展设置共享任务协议；备份、迁移与恢复面向歌曲和资产，避免要求用户逐条修复路径或手动维护内部文件。
- P20：按来源台账逐项关闭旧应用实现；退役原生 UI、CLI、AI wrapper、旧打包与样式从产品依赖和发布入口退出。通用依赖及第三方资源单独记录。
- P21：完成原创应用层来源审计；新实现记录规格、作者/生成来源和依赖。没有路径匹配不等于原创证明；历史版权不通过批量改名删除。完成替换后再决定新原创基线的导出方式，现有远端历史不在本计划中强制改写。
- P22：制作来源对应的 Release 包，完成一次独立启动和一组完整练琴流程；更新截图、使用说明与实际限制。普通练琴可交付和原创替换完成分别下结论。

## 执行与验收

每轮推进一批彼此关联的实际改造。允许重构和替换现有实现，保护用户数据。纯文档整理只核对链接与事实；依赖/入口改动做 metadata 或受影响编译；行为改变只做直接覆盖该风险的检查。数据迁移必须核对内容与可回退性。每批通过的构建不重复运行，正式打包集中在形成可用里程碑时。

每两小时主动核对用户目标、当前任务、前台入口、来源替换、用户数据和实际交付差距。允许在目标内调整任务顺序和 Goal 执行文件；新增功能范围仍按用户指令决定。检查机制见 current-goal.md 与 goal-state.json。
