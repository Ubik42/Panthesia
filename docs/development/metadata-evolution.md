# 曲目资料扩展与兼容

更新：2026-11-19。对应官方功能 L03、C10、C12。

## 数据归属

`panthesia_core::library::SongMetadata` 继续为歌曲个人资料的声明来源，生成 TypeScript 契约。新增 `subtitle`、`arranger`、`copyright`、`license`，均为可空文本。旧文件缺失字段时读取为空。归一化保留原有去首尾空格规则。

`LibraryProvenance` 与 `SongRow.license` 继续表达素材来源信息。个人填写的许可说明保存在 SongMetadata，不覆盖素材来源许可。改编者作为独立查询字段投影到 SongRow。第三方描述资料的来源默认值 / 个人覆盖规则见 [资料分层](metadata-defaults.md)。

## 编辑与保存

曲目信息编辑器增加四个中文字段。字段清单由 `features/library/metadataFields.ts` 提供，供编辑器、历史恢复、草稿与数据核对共用。每项最多 2000 字，保存继续使用原版本比较和事务，指法、分手及原谱关联保留。旧编辑草稿在恢复时补齐四个空字段。

曲库管理中的字段查询包括 `composer:`、`arranger:`、`tags:`，可与普通词、双引号短语和 `-` 排除结合。例如：

```text
composer:"Porter Robinson" tags:练习 -title:试听
arranger:教师 "第一乐章"
```

明确字段条件优先于界面的默认搜索字段。未知前缀和 Windows 路径继续按普通文字处理；输入未闭合引号时继续筛选当前已输入内容。

## 版本规则

| 容器 | 扩展资料存在时 | 无扩展资料时 | 读取兼容 |
| --- | --- | --- | --- |
| MIDI 附加资料（兼容后缀 `.neothesia.ron`） | v2；来源分层使用 v4 | v1 | 接受 v1–v4；含逐音规则使用 v3 |
| `.neopiece` 曲目包 | v13；来源分层使用 v15 | 原最低所需版本 | 接受 v1–v15；含逐音规则使用 v14；旧版本声明夹带扩展字段会被拒绝 |
| 练习备份 | v17，扩展资料随资料历史保存；扩展模板使用 v19 | 原最低所需版本 | 接受 v1–v19；历史包含逐音规则时使用 v18；声明版本不足会被拒绝 |
| 资料历史及待认领历史 | v2 | v1 | 接受 v1 / v2 |
| 资料模板注册表 | v2（含新增描述字段） | v1 | 接受 v1 / v2，版本不足时拒绝写入 |

这次没有把个人资料改成新目录，也没有迁移用户正式数据。版本由内容决定；读取本身不会批量改写旧文件。旧版本程序通常只接受原格式，因此含新字段的资料应继续使用本轮或更新版本处理。曲库索引属于缓存，原 sidecar 和历史仍为保留资料的依据。

## 当前验证边界

已有 sidecar 往返检查已扩展到四个新字段。新增一个曲目包与备份的组合检查，确认新字段往返、版本声明以及低版本包拒绝。UI 使用隔离资料根操作，检查字段保存、读取和改编者查询。具体结果见长期开发交接。

官方 `.synthesia` 格式适配及逐音播放规则已实现首批，详见 [导入说明](synthesia-import.md) 和 [逐音规则](note-playback-routing.md)。描述资料分层、双入口恢复、扩展模板及演奏页信息展示已完成；自动发现、元数据导出和评级分层仍在对应清单中。
