# 钢琴瀑布流连续滚动修正

日期：2026-11-18。用户进一步确认卡顿主要表现为钢琴瀑布流一顿一顿。运行包：`outputs/releases/Panthesia-20261118-waterfall/Panthesia.exe`。

## 已复现的直接原因

前端约每 80 ms 读取一次后台状态。原瀑布在 `required.length > 0` 时停止时间补间和连续动画调度。连续练习的待评分音符也会进入 required，因此它被错误地按等音暂停处理。

演出粒子存在时，画布仍可能每秒执行 60 次绘制，但多数帧复用了同一个音符位置。较少光效时，动画调度本身也会停止，只在下次状态到达时绘制。此前仅统计绘制回调频率，无法区分这两种情况；本轮增加了位置、位移与回退记录。

另一个抖动来源是收到状态后重新用收到时刻作为起点。状态传输和 React 提交的时间差会让原位置预测反复跳回。本轮移除瀑布对逐次 React 提交的依赖，并对小幅时序差异做平滑校正。

## 实现

- `waterfallClock.ts` 提供只读显示时钟。只有“等音且确实等待目标音”才冻结画面；连续模式保持逐帧滚动。
- 正常播放中的小幅时间误差逐渐校正，音符不因此回退；定位、循环、换曲、暂停及返回隐藏窗口时按后台位置重新同步。
- 对断流保留 120 ms 的有限预测范围，显示不无限脱离后台；当前位置也不会越过练习选段的末端。
- 瀑布直接订阅播放存储，后台状态更新不再要求 React 重新提交钢琴子树。发声、评分和等音判断继续由引擎负责。
- 音符主体与辉光使用小尺寸分段纹理，上端、中段和下端分别绘制。拉伸持续时间时保留圆角和端点光晕；纹理缓存上限为 128 项、约 8 MB。
- 舞台背景和琴键材质按尺寸与外观缓存；音符标签的尺寸与颜色复用。普通练习时不创建逐帧的指法编辑命中对象。
- 小节、拍和细分网格按样式合批绘制。画布尺寸在实际布局变化时测量，绘制循环不再每帧调用布局读取。
- 保留皮肤、三种琴键材质、光效、网格设置、屏幕琴键演奏和逐音编辑入口。
