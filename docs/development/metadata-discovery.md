# Synthesia 资料目录发现与导入范围

更新：2026-11-19。对应 C12 的目录发现与已有导入链衔接。自动发现已完成；自动加载并生效继续列为下一批功能。

## 官方要求与当前行为

[内容作者指南](https://synthesiagame.com/support/guide/contentCreators) 说明，监视目录中的 .synthesia 文件会自动加载，歌曲分组也会自动出现。[官方格式](https://github.com/Synthesia-LLC/metadata-editor/wiki/File-Format) 还允许资料文件位于正在演奏的歌曲所在目录。

本批完成目录发现、匹配、范围展示和从目录来源直接预览 / 应用。当前仍由用户选择来源并确认应用。后续需把已验证来源接入自动加载、个人标注覆盖及同曲多来源处理，才能满足完整自动加载行为。C12 继续保持部分完成。

## 使用

1. 在曲库管理选择 1～64 首 MIDI，打开“曲库工具 → 导入 Synthesia 资料”。
2. 导入窗口列出目录中已发现的资料文件、源文件歌曲数、匹配所选曲目数，以及已应用当前版本 / 已有其他来源版本的数量。
3. 可展开本次导入范围查看曲名和原 MIDI 路径。默认隐藏未匹配的有效文件；损坏文件和待索引文件继续显示。
4. 选择来源、预览匹配，再应用所选内容。原有手动选择文件入口继续可用。
5. 重新查找会核对登记目录，自动更新暂停时也可使用。应用后重新打开曲目使用新的指法和逐音播放规则。

## 范围与性能

- 自动发现复用曲库监视器的目录遍历，同时收集 .synthesia 路径；歌曲列表和资料来源分开维护。
- 已登记曲库目录递归查找，沿用最大 12 层 / 20000 目录边界并跳过符号链接。额外检查主曲库根目录的直接子文件。
- 打开导入窗口时，读取后台索引并检查所选 MIDI 所在目录的直接子文件；手动重新查找会重新遍历登记目录并核对来源。
- 索引上限 128 份来源；每份最大 2 MB，每轮解析预算 16 MB，超额显示待索引状态或范围说明。手动文件选择可用于未纳入索引的来源。
- 未变化的来源复用解析结果，后台轮询不克隆整份歌曲身份列表；来源歌曲身份排序后按二分查找匹配所选 MIDI。
- 仅维护独立的发现缓存，不在发现过程中修改 MIDI、资料、指法或分组。解析与匹配均在已有后台任务通道运行。

## 边界

`metadata_discovery.rs` 管理有界缓存、扫描结果、内容匹配和来源读取；`synthesia_import.rs` 继续负责格式解释、预览和导入；`library_edits` 继续负责编辑事务准备与发布。前端使用从 Rust 生成的来源候选与查询契约，共用已有导入窗口。

缓存为 `synthesia-discovery.json`，属于可重建索引。提交时核对用户所选来源的实际内容标识；来源变更需要重新选择与预览。来源原文件作为事务依赖，预览后或准备期间被改写会拒绝提交。

导入成功回执按来源内容、目标 MIDI、选项和预览证明绑定。相同请求重试先读取已保存回执；原来源之后移走时也可确认此前完成结果。新请求继续核对当前原文件。
